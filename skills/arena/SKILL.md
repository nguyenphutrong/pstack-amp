# Arena

Read [Amp execution rules](../poteto-mode/references/amp-runtime.md).

1. Frame. Name the artifact, same candidate brief, and three to six criteria. Keep the rubric private from candidates. Choose the count from the user's request, otherwise use two meaningful alternatives. Confirm exact input state and output ownership.
2. Fan out. Explicit arena invocation requests independent attempts. Use bounded Tasks dispatched together when the shared checkout and disjoint output paths suffice. Each candidate gets the same goal, constraints, verification contract, its own output path, and a rationale of rejected alternatives. For isolated persistent ownership use supported thread tools with an explicit code-transfer plan. Never let competing writers share one branch or directory.
3. Cross-judge. Wait until candidates finish writing. Obtain an independent judge where the tools and authorization allow it. The judge sees the rubric and sanitized candidate labels, not model identities. Task cannot select a model; same-model attempts are not cross-model diversity. Use explicitly selected available modes only when independent thread execution is appropriate. Do not invoke Oracle merely to fill a panel.
4. Pick. Read every artifact yourself. Score criterion by criterion and compare the judge's reasons. Select a base, not a vote. Record dropouts and incomplete criteria.
5. Graft. Integrate useful ideas from losing candidates into one coherent design. Record what was kept, rejected, and why. Convergence needs no forced graft. Wild divergence may mean the brief needs reframing.
6. Verify. Run the synthesized result against the original brief and actual behavior, not candidate summaries. Preserve proof artifacts, then clean only owned scratch outputs.

Return one artifact and synthesis note with base, grafts, rejections, dropouts, actual reviewers or modes, and proof. If independent judging was unavailable, state that gap instead of claiming an independent verdict.
