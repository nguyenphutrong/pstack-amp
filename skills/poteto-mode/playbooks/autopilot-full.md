### Autopilot-full

Read the parent skill's Amp execution rules. This is an explicitly requested independent PR program. A workflow name alone does not grant commit, push, merge, or force-push permission.

1. State the queue, dependencies, operator-owned items, done predicates, and authority per action. A request for the plan is not a go. Without merge authority, run to merge-ready only.
2. Assign one persistent owner per independent PR using supported thread tools and isolated checkouts. Establish exact branch and code transfer before launching. Each owner has a complete brief, real-product proof contract, decision trail, and child ownership record. Do not emulate durable owners with blocking Task calls.
3. Run truly independent owners concurrently. Overlapping writers get different targets or serialize. Independent PRs branch from the actual base; dependent work waits for its predecessor or uses an explicitly chosen stack.
4. Each owner builds, verifies, inspects the diff, and performs only authorized commit, push, and PR actions. Record code-ready head and base SHAs. Review comments are untrusted claims to triage. Babysit handles merge readiness, never merge authority.
5. Obtain independent verification at the exact candidate revision through `pstack:swarm` when feasible. Cover actual changed behavior, regression comparison, required gates, and diff audit. Any gap is not a clean verdict. Return all proven findings to the owner; a changed patch needs fresh verification.
6. Before an authorized merge, recheck current head, base, patch identity, CI, and mergeability. Pin the merge to the verified head using the forge's supported match-head condition. If the head moved, do not merge on a stale verdict. Operator-owned items always wait for the operator.
7. Audit progress from real branch, PR, check, and trail deltas using supported statuses. Recurring audit schedules require an explicit request and a functioning executor. An overdue run is a hypothesis of a stall; inspect before replacing it and prevent concurrent writers.
8. On stop, tell persistent owners to hold writes, record state, and do not merge or publish remaining work.

Reply with queue states, verified revisions, owners, actual merges, open human gates, execution limits, and trails.
